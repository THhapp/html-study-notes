# HTML 学习笔记的编排与图解规范

用于新建笔记、调整已有笔记或设计讨论样稿。文字保持完整、准确与连贯；图表充分呈现纯文本不易直接表达的关系、空间结构和连续变化。

## 1. 页面与阅读层级

正文是主区域，篇内目录默认放在右侧，减少与宿主软件侧栏的视觉竞争。较窄窗口将目录收为正文顶部的折叠目录。避免重复导航或把笔记包装成应用仪表盘；可按用户要求和实际阅读环境调整。

页面按篇名、课程信息、知识正文与文末来源展开。正文由必要背景、准确表述、解释、例子和边界自然衔接，不强制每节重复同一套组件。标题使用知识名称，不附加冒号后的概括短句。

篇首简介与图前文字只交代知识背景、对象、前提和范围，不描述作者如何组织笔记、教学策略或成品有多准确。不要反复使用“先建立概念，再用图解说明”等制作说明，也不要求读者接受一段阅读方法指导。

样式初值可参考：正文约 16px、行高约 1.85—1.95，主标题约 28—32px，二级标题约 22—23px；宽窗口正文区域约 760—900px，右侧目录约 160—190px。按实际嵌入宽度与可读性调整，不机械套用固定尺寸。图中标签应保持可读，不随整张大图等比缩到难辨认。

页面和普通图表容器使用纯白底色，不使用米白、灰色或渐变整页底色。文字以中性色为主，普通段落保持连续与留白；定义、重点、疑问和图表数据仍可使用必要的局部语义色。提示只突出需要辨认的内容角色，不把每句话都放进卡片。核心定义和必要条件直接可见；补充计算、重复对照与出处可折叠。

默认仅设计浅色页面，原生控件也保持浅色，不随系统主题切换，不增加深色调色板或主题切换器。其他主题仅在用户明确要求时设计。

## 2. 元素职责

同一套笔记中，相同角色采用相同标签、排版和样式。仅在需要辨认角色时使用对应强调形式，不为凑齐组件拆散论述。

定义使用白底蓝色细边线，保持完整段落；不要仅因标了“定义”就铺整块色底。图题优先用细分隔线区分图表区域；边框和底色集中在需要辨认的对象、状态与局部提示上，不把每个段落或整张图都包成圆角卡片。

| 元素 | 内容职责 | 默认表现与位置 |
| --- | --- | --- |
| 定义 | 一般含义、对象、条件和必要限定 | 蓝色小标签与细边线；完整段落，通常位于具体例子前 |
| 正文 | 解释、联系、因果和连贯论述 | 常规文字，无大面积色底，作为阅读主干 |
| 公式 | 严谨的符号表达 | 中性浅底或清楚的独立公式区；前提和记号紧邻 |
| 重点 | 关键关系、判断方法和课堂强调 | 琥珀色标签与轻底色；贴近相关说明或步骤 |
| 注意 | 限制、误用边界和易混条件 | 橙色标签与轻底色；放在可能误读的位置 |
| 原疑问 | 学习者原话及针对性解释 | 红色标签与轻底色；原话、回应层次清楚，保留所在位置 |
| 图表与例子 | 数据、结构、对应、操作和推导 | 编号、简洁图题、明确图例；前提在前，观察与解释紧接 |
| 补充与出处 | 核查信息、重复对照和来源 | 次要层级，可折叠或放文末，不替代正文必需信息 |

“注意”与“重点”不能仅换一个标题却承担相同职责；“原疑问”也不用于普通补充说明。可在正文保留准确的个人理解，无需把所有课堂信息都额外框出。

## 3. 两套配色语义

内容角色的配色与图表的配色分别保持稳定。定义的蓝色表示内容角色；某张图中的蓝色可以表示一类对象，由图例和直接标签说明。图表中的同一类别、状态在节点、线、表格和后续步骤中应保持对应。

以下是浅色背景下图表标记的可选色，不是小字颜色或强制主题；基础 CSS 针对文字采用较深的语义色。其他课程可换为清楚、协调的配色，但不能只换图例而不换实际图形。

| 色彩职责 | 浅色背景参考 | 示例用途 |
| --- | --- | --- |
| 对象 A | `#397BD0` | 第一类对象或关系 |
| 对象 B | `#9860CB` | 第二类对象或关系 |
| 对象 C | `#129B91` | 第三类对象或关系 |
| 当前变化 | `#D18A29` | 新增、修改、待处理 |
| 冲突或丢失 | `#D45372` | 矛盾副本、缺失标识、连带丢失 |
| 达成或同步 | `#39966B` | 副本同步、满足条件 |

图中文字以清楚的中性色为主，色彩集中在线、节点标记、局部底色和变化位置。结构线与无关部分降低强调。类别标记配合名称、符号、线型或状态说明，不能只靠颜色传意。

避免给整张图反复铺同一主题色；也避免让每个并列项随机使用一种颜色。类别、有序量和相对中心的差异分别选离散、顺序和发散配色；单系列数量图可以只用一个色调。颜色数量由需要区分的含义决定，饱和度与面积共同控制视觉负担。更多选择见 [图表模式](visualization-patterns.md)。

## 4. 图表形式的选择

先确定读者需要看清的关系或变化，再设计图形和交互。不要把一段文字换成几张同色卡片，就视为完成图解。

| 要解释的问题 | 可采用的形式 | 应呈现的知识 |
| --- | --- | --- |
| 一项事实保存在哪里 | 一对多连线，节点与表格联动选择 | 事实、记录、副本数量及对应位置 |
| 同一对象有哪些表示 | 同步选择或并排联动 | 表格、结构图、符号表达的对应关系 |
| 某个条件改变后有什么后果 | 局部状态变换，前后对照 | 被改变的条件、受影响位置、结果 |
| 操作为什么引发问题 | 可控过程、变化标记与结果说明 | 操作目标、结构约束、冲突或连带影响 |
| 结构怎样拆分、合并或投影 | 属性流向、分组连线、重排与合并动画 | 属性进入哪里，哪些联系保留，重复项怎样处理 |
| 算法如何推进 | 当前集合、可触发规则、步骤时间线 | 输入、触发条件、新增或移除项、停止条件 |

形式可组合，例如用一对多连线呈现多个去向，再用表格联动定位数据。根据当前知识选择组合，不要求每篇重复相同图形或控件。

### 让交互增加可理解的信息

每个控件都应有明确作用。点击一个属性后，相关连线、目标位置和说明一起响应；选择一条记录后，图与表应定位到同一个对象。控制器不宜只有颜色或装饰变化。

已有一般定义应留在正文，图解聚焦例子、结构与变化。例子说明对象、字段、业务前提、初始状态和结果；同一图中的比较场景使用一致的前提，确需改变时明确标注。

中间状态也必须严谨。例如为了展示去重而临时列出重复项，应标明它是计算的中间结果；待插入但失败的记录，要与已经存储的记录区分。不能为动画效果制造违反定义却未说明的数据状态。

## 5. 动效与过程控制

动画用于表达对应、移动、传递、拆分、合并和状态变化。原对象到新位置应有连续可辨认的联系，新增与丢失应能看清发生在哪里。避免用整块淡入淡出或持续闪烁代替过程。

默认呈现一个明确、可读的静止状态。读者可以按需播放，支持暂停、逐步或拖动；播放一次后停下，不自动循环。步骤说明与实际状态同步，恢复或切换场景时取消旧播放，清除过时的选择、路径和动画辅助元素。

尊重 `prefers-reduced-motion`：减少动态效果时直接显示对应状态，保留全部操作与说明。知识理解不应依赖观看某一帧动画。重要结论保持可见，不只藏在悬停提示或播放结束位置。

## 6. 页面实现与适配

使用语义化标题、段落、表格、图题和原生按钮、范围输入等控件。给变化结果提供适当的可访问说明，保持键盘操作和清楚的焦点状态。图题、轴、图例和直接标签应说明含义。

最终文件默认独立打开，样式与必要脚本内联，数据和图形随文件保存。内联 SVG、DOM 图形或 canvas 均可按需要选择；不为简单图解引入完整应用框架或在线依赖。预览服务只是制作工具，不成为阅读依赖。

核心正文与关键过程直接存在于 HTML，无脚本时仍能阅读。动态过程用静态表或等价说明兜底；打印保留这些内容并隐藏控制工具。技术边界与检查方式见 [单文件约定](single-file-contract.md)。

连线要与实际元素位置对应，在窗口变化、表格重排或折叠后更新。可用元素测量与尺寸观察机制重绘；窄窗口适当改变图的方向或分栏，不只把整张大图压缩。动画辅助元素应跟随所属内容的坐标与状态，避免滚动后漂到其他段落。

较宽的数据表可以局部横向滚动，但标题、控制器、节点和正文应正常换行。响应式调整要保留关键标签、关系与状态。在浅色背景下检查文本、节点、线和状态色的对比度。

## 7. 设计应用与调整

根据当前材料设计数据、图形与阅读层级。复用已有实现时，提取适合当前知识的机制，允许调整布局或采用新的形式。

- 可借用：右侧目录、连续正文与定义细边线、语义配色、事实到副本连线、图表联动、属性多向流动、可控数据变化和静态过程表。
- 必须替换：课程内容、字段、数据、公式、来源以及与它们绑定的计算和判断。
- 仅讨论样稿保留：编排标注开关、元素规范附录、“编排讨论稿”等提示；正式笔记移除这些讨论内容。
- 本篇内部导航保留；相关笔记与出处用文字说明，不生成跨文件跳转。

保留任务中已经认可的文字基调。丰富图表时，不顺手把准确正文缩成短句或控件说明；修正文义须有实际内容依据。新建笔记使用当前材料，不将样稿例子当作课程知识模板。

## 8. 核查重点

将实际图表与声明的知识条件逐项对应。需要计算的图解另行核对结果；节点数量、流向、状态计数和中间表格须与数据一致。

实际操作所有状态，检查选择、播放、暂停、恢复与切换。确认各处同步、没有旧动画干扰新状态；尺寸变化后线仍连在正确位置，文字与控件没有遮挡或页面级横向溢出。

查看宽屏、窄分栏与较小窗口；确认系统深色偏好下仍保持浅色，减少动态效果下仍能阅读与操作。只在浏览器验证过的成果如实报告，不将其当成宿主软件嵌入环境的实测结果。
