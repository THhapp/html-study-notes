# 可视化的视觉设计

用于静态图、局部交互或独立 HTML 演示。设计围绕读者要看清的结构、对应、数量与变化，不承担完整学习笔记的编排。以下提供选择依据，样稿与现有 CSS 只是可复用实现。

## 视觉主线与布局

让主要图形占据合适空间。标题、必要前提、标签、控制与结果围绕图形组织；不为演示补写完整课程正文，也不把长段讲解换成同色卡片。

布局跟随知识关系：并列有助于比较，连接适合追踪去向，分区有助于区分阶段或层级。可以采用多图联动或一个聚焦视图，不规定栏目、图数或控件数。短演示通常无需目录；内容较多时再按实际窗口安排导览，不默认固定右侧目录。

按实际可用宽度调整空间。标签不应随大图整体缩到难以辨认；先考虑重排、减少无关细节、局部放大或局部滚动。窄分栏中，标题、说明和控件仍应正常换行，避免整页横向溢出。

已有 MD 主文时，图解使用同样的记号和例子，但只携带理解当前图形所需的信息。主题分篇、callout 与正文结构由主任务决定。

## 标签、前提与结果

对象、边、坐标、单位和状态的含义要能辨认。直接标签通常比远处图例易于对应；符号较多时使用就近图例或按需细节。图题和编号按任务需要设置，不要求每张图都编号。

用短说明交代图的输入、前提、可变条件和结果。正式状态、计算中间态、待执行和失败操作应明确区分，不能为了动画制造未标明的非法数据。

对比场景尽量保持相同尺度与前提；确需改变时标明变化处。关键条件与结果不只藏在悬停提示、播放末尾或默认折叠区。

## 颜色与强调

默认白底浅色，文字与结构线以清楚的中性色为主；任务已有主题时按要求适配。节点、边、局部底色和变化位置可用语义色，颜色数量由需要区分的含义决定，不由组件数量决定。

- 类别使用离散色，有序量使用顺序色阶，围绕有意义中心的偏差可用发散色。
- 同一对象在节点、表格和步骤中保持身份对应；当前选择可叠加外框、粗线或文字，不必反复改变对象本色。
- 状态色有明确含义，避免整图铺同一种高饱和色，或让每个对象随机拥有一种颜色。
- 颜色配合标签、符号、形状或线型，不能成为唯一信息。图表线条色不直接用于小字，文字和图形分别考虑可读性。

配色和强调形式可随内容调整，不从旧示例推导“定义必须蓝色”“疑问必须某种卡片”等要求。

## 交互与动效

每个操作应让读者看到有意义的信息：选中源时定位相关去向，改动参数时更新受影响对象，单步推进时呈现触发条件与本步差异。仅改变装饰色不等于完成解释。

用稳定标识维持多种表示的一致性。步骤说明、图形、表格和计数来自同一当前状态；重置或切换场景时清理旧播放、选择与路径。

位移适合追踪对象去向，高亮适合指明本步变化。连续闪烁、整图淡入或无关计数滚动不自动增加理解。插值动画用于位置过渡，不冒充新的领域合法状态。

默认提供可观察的静止状态，让读者控制过程。按需要提供单步、拖动、播放或暂停，不要求凑齐一组按钮。展示周期机制时可以循环，但应能暂停。减少动态效果时直接显示对应状态，保留等价操作与结果。

## 实现与适配

静态 SVG、Mermaid、DOM/CSS、Canvas 或绘图工具按实际需求选择，不为简单图强加框架。交互用语义清楚的按钮和输入，保持键盘操作、焦点与反馈可见。复杂图提供适量的结构或数据说明，避免只剩一个无解释的画布。

连线使用一致坐标空间。窗口变化、重排或折叠后重新测量必要的端点；可选参考 `assets/diagrams.js`，也可自行实现。动画辅助元素与所属图保持相同坐标和生命周期，避免滚动后漂移。

按需要保留静态结果、关键帧、过程表或结构摘要，方便扫读、打印与无脚本查看；不要求为此复制一整篇知识正文。独立 HTML 的技术细节见 [交付约定](single-file-contract.md)。

## 参考与核查

复用样稿时，提取适合当前问题的机制，重新核对数据、算法、符号和来源；不要遗留示例术语。可以重新设计图形与布局，样稿中的目录、配色、边框和文字量都不是验收清单。

核对当前成果的模型与计算，再实际查看图形和操作。检查关键状态、尺寸变化后的连线、标签可读性以及本次涉及的切换行为；按实际验证环境报告结果，不把浏览器检查说成宿主内嵌验证。
