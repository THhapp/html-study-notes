# 可视化制作流程

用于把指定知识、数据或过程转成视觉表达。按任务需要往返调整，不是每张静态图都要执行一套完整交互开发流程。

## 明确视觉问题

从当前任务、已有主文和必要材料确定要展示什么、输出在哪里、哪些内容已认可。只读取理解当前图解所需的范围；原始课件与手写记录不是默认的全量整理任务。输出是局部演示时，不扩展到笔记分篇、正文撰写、插件开发或宿主配置。

把问题具体化：读者需要辨认哪些对象、哪种关系、哪一步变化或哪个条件的影响？若静态图或并列状态已能看清，不额外设计互动。

## 建立数据与状态模型

实现前按复杂度理清有关内容，不要求填写固定表格或另交一份设计文档：

- 对象与身份、关系方向、单位、输入数据及可变参数。
- 适用前提和不变量，如数量守恒、键唯一、集合包含或边方向。
- 一次操作改变什么，哪些图形、表格、说明和计数应一起更新。
- 初始、过程、结果以及有意义的边界状态；哪些只是布局过渡，不是领域状态。
- 怎样核对模型和计算，是否需要静态结果或过程摘要。

符号与主文一致。若发现前提缺失、材料矛盾或计算有误，具体说明并在当前授权内修正，避免把错误画得更有说服力。需要计算时，由领域逻辑生成结果或帧；通用控制器只调度与展示，不证明数据合法。

## 选择形式并实现

参考 [图表模式](visualization-patterns.md) 选择静态图、关系联动、条件对照或过程演示，参考 [视觉设计](design-system.md) 安排图形、标签、控件和结果。

先做能表达关系与结果的图，再加入有收益的互动。需要复用时只读取对应控制器和例子，不把旧页面作为必须填满的空模板。现有组件名和 API 保持兼容，不要求新图采用同样布局或术语。

多图或复杂交互可先完成一个有代表性的局部，核对后再扩展；小图直接完成即可。说明文字服务于当前图形，不重复主文，也不加入自评质量或制作方法的套话。

## 必要核查与交付

计算与表现分开核对。交互涉及哪些操作，就验证相应状态的一致性，例如切换、暂停、重置是否留下旧计时器或路径；静态图则关注标签、关系和结果，不套用播放测试。

实际查看目标窗口中的图形和控件。按交付内容检查窄窗口、局部滚动、键盘操作、减少动态效果或打印表达；不为未采用的能力补测试，也不重复回归未改动的通用实现。

独立 HTML 默认可直接离线打开。静态结果或关键过程按需要保留；已有页面中的可视化遵循宿主接口。既有静态检查器有较窄适用范围，详见 [HTML 交付](single-file-contract.md)。

交付约定格式的图或演示，简述呈现什么、能操作什么、实际核对范围与具体限制。浏览器验证不代表已在 Obsidian 内嵌测试。制作文件和证据留在工作区，展示成果保留图形与必要说明。
